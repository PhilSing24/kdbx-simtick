# di.simorder parameters

Generated by `genparams.q` from `simorder.describe[]`; the shipped values are those of the `good` order row composed with the US large-cap market file. Do not edit by hand: run `make params`.

An order's configuration is composed from the market file's `orders` group (and its `ticksize`) and an order row (`di/simconfig/orders.csv`); a row may override any market key. `urgency` and `maxpct` are read for arrival pacing only.

## Order row

| Parameter | Type | Description | Shipped value |
|---|---|---|---|
| `orderid` | symbol | unique order identifier | ORD001 |
| `sym` | symbol | ticker symbol - must match the trades/quotes tables | NVDA |
| `side` | symbol | BUY or SELL | BUY |
| `orderqty` | long | total order quantity | 10000 |
| `starttime` | timestamp | execution window start (timestamp, matches trades/quotes date) | 2026.08.18D09:35:00.000000000 |
| `endtime` | timestamp | execution window end (timestamp, same day) | 2026.08.18D09:45:00.000000000 |
| `numchildren` | long | number of child orders to send (a cleanup child may follow) | 20 |
| `pacing` | symbol | child scheduling: even (patient), frontloaded (rushed) or arrival (urgency trajectory under a participation cap) | even |
| `spreadcapture` | float | probability a child is aggressive (a marketable order crossing the spread) rather than passive (a limit at the near touch): 0=best, 1=worst | 0.1 |
| `account` | symbol | the account the order is for | ACC1 |
| `algo` | symbol | the algorithm working the order (a label: VWAP, IS, ...) | VWAP |
| `seed` | long | random seed of the jitter, the aggression and the venues (0N = no seed) | 1 |
| `urgency` | float | arrival pacing only (required there): Almgren-Chriss urgency (kappa x horizon), positive; higher trades earlier |  |
| `maxpct` | float | arrival pacing only (required there): participation cap per interval, own/(own+market), between 0 and 1 |  |

## From the market file

| Parameter | Type | Description | Shipped value |
|---|---|---|---|
| `ticksize` | float | minimum price increment; fill prices sit on the tick or exactly at the midpoint (half ticks) | 0.01 |
| `latencyms` | float | milliseconds from a child's send to its arrival at the market (and half of it to its ack) | 2 |
| `maxreplaces` | long | how many times a passive child re-pegs to the near touch when it moves away, before resting where it is | 20 |
| `jitter` | float | random shift of each child's time, as a share of half the gap to its neighbours, between 0 and 1 (0 = exact schedule) | 0.3 |
| `capacity` | symbol | A (agency) or P (principal) | A |
| `ordervenues` | symbol list | lit venues (MIC codes) the children are routed to | XNAS ARCX BATS EDGX |
| `ordervenueshares` | float list | their routing shares (sum to 1) | 0.4 0.2 0.2 0.2 |
| `sweepticks` | long | ticks beyond the touch at which the rest of an aggressive child fills once the displayed size is taken | 1 |

## Market file: algo menu, order-flow defaults and impact

Read by `simorder.generate` (any spec key overrides the market's) and `simorder.impactcfg`.

| Parameter | Type | Description | Shipped value |
|---|---|---|---|
| `algos` | symbol list | di.simorder: the algo menu an order flow draws from (labels) | VWAP IS AGGRESSIVE PASSIVE |
| `algopacings` | symbol list | di.simorder: each algo's pacing (even, frontloaded or arrival) | even arrival frontloaded even |
| `algospreadcaptures` | float list | di.simorder: each algo's share of aggressive children, between 0 and 1 | 0.1 0.35 0.9 0 |
| `algourgencies` | float list | di.simorder: each algo's urgency (arrival pacing only, null otherwise) |  2   |
| `algomaxpcts` | float list | di.simorder: each algo's participation cap (arrival pacing only, null otherwise) |  0.2   |
| `norders` | long | di.simorder: orders per instrument and day of a generated flow | 5 |
| `accounts` | symbol list | di.simorder: the accounts a generated flow draws from | ACC1 ACC2 ACC3 |
| `sizepct` | float list | di.simorder: lowest and highest order size of a generated flow, as a share of the day's volume | 0.005 0.05 |
| `windowminutes` | float list | di.simorder: shortest and longest order window of a generated flow, in minutes | 10 60 |
| `childrenperminute` | float | di.simorder: children per minute of window of a generated order (at least 5 children) | 2 |
| `orderimpactmodel` | symbol | di.simorder: impact model of the child executions, participation (p^beta) or sqrtlaw | participation |
| `orderimpacteta` | float | di.simorder: impact coefficient, zero or positive (0 = no impact) | 0.01 |
| `orderimpactbeta` | float | di.simorder: participation exponent, positive (0.5 is the square-root law) | 0.5 |
| `orderimpacthalflifeseconds` | float | di.simorder: seconds over which the transient part of an execution's impact halves | 300 |
| `orderimpacttaperminutes` | float | di.simorder: minutes before the close over which the impact shift falls linearly to zero | 5 |
| `orderimpactpermanent` | float | di.simorder: share of each execution's impact that stays through the day, between 0 and 1 | 0.3 |
